# 国赛 C 题数据驱动建模方法卡

本文件用于全国大学生数学建模竞赛中以附件数据为核心、同时包含描述、预测、评价或优化的 C 题。
它不是对未来题目的题型预测，也不把“C 题”绑定到固定算法。正式任务仍先读取 `README.md`、
`00_建模前必读.md`、`00A_证据与质量门禁.md`、`知识库/基础方法/01_问题识别与模型选择.md`，并始终读取
`知识库/基础方法/11_验证敏感性与不确定性.md`。

## 1. C 题的首要判断

先把题目拆成四份契约，而不是先列算法：

1. **数据契约**：每行代表什么，主键、时间、单位、缺失、重复和附件间连接关系是什么；
2. **统计契约**：要描述总体、解释关联、预测未来、识别类别，还是估计潜在量；
3. **决策契约**：哪些量可控制，目标和硬约束是什么，方案在现实时间顺序上是否可执行；
4. **证据契约**：题面数据能支持多强的结论，哪些外部事实、参数和规则必须动态核验。

题目中的“分析影响”“给出方案”“预测”“评价”不是模型名。先写交付项—变量—证据表，再选择
能完成任务的最简单模型。

## 2. 附件数据的高风险结构

### 2.1 数据字典先于清洗

至少登记：字段名、业务含义、类型、单位、允许范围、缺失语义、观测时点、生成机制、可用时点、
主键和来源文件。`0`、空白、`-1`、检测下限、未发生、未记录不得自动合并。

### 2.2 连接与粒度

- 连接前检查一对一、一对多还是多对多；连接后核对行数、唯一键和聚合口径；
- 同一主体多次观测不是独立样本；主体、批次、地区、设备或机构应进入分组划分；
- 日、周、月数据混合时，先确定聚合窗口和信息截止时点，禁止让低频未来汇总量进入高频特征；
- 先画数据血缘：原始字段 → 清洗字段 → 特征 → 模型输入 → 表图与结论。

### 2.3 特殊结构识别

- 比例和组成数据受闭合约束时，考虑 log-ratio 方法，不在原比例空间机械做普通相关；
- 截尾、删失、检测上下限与普通缺失不同，必须使用相应似然或区间信息；
- 空间、网络、层级和重复测量数据不能默认独立同分布；
- 由标签、结局后信息或全样本统计量构造的特征属于泄漏候选。

## 3. 基线优先的模型路由

| 目标 | 第一基线 | 条件升级 | 最低验证 |
|---|---|---|---|
| 时间预测 | 最近值、历史均值、季节朴素 | ETS、ARIMA/动态回归、树模型、深度时序 | 滚动起点、分预测步长误差、区间覆盖 |
| 表格回归 | 均值/线性或正则回归 | RF、GBDT、XGBoost、神经网络 | 按时间/主体划分、残差分层、训练外误差 |
| 分类 | 多数类、Logistic | 树集成、SVM、神经网络 | PR/ROC、阈值成本、校准、混淆矩阵 |
| 聚类 | 业务规则或简单分箱 | K-means、层次、DBSCAN、GMM | 尺度、稳定性、外部有效性、噪声口径 |
| 关联模式 | 单变量频率和交叉表 | FP-Growth、序列/网络模式 | 支持度稳定性、多重比较、非因果声明 |
| 综合评价 | 单指标或等权 | TOPSIS、PCA、DEA 等 | 权重/方向/归一化敏感性、排名稳定性 |
| 资源配置 | 贪心或现行策略 | LP/MILP、CP-SAT、动态/鲁棒优化 | 可行性、界/gap、压力情景、实现成本 |

升级条件必须来自数据结构或决策需求。算法数量、网络层数和图表数量均不是质量证据。

## 4. 预测任务的竞赛级协议

### 4.1 信息截止时点

对每个特征写明“在预测时是否已经知道”。滞后、滑窗、编码、插补、标准化、特征筛选和超参数选择
均在每个训练窗口内完成。时间序列不得随机打乱后交叉验证。

### 4.2 回测

滚动起点 \(o_1<\cdots<o_K\)，预测步长 \(h\) 的误差写为

\[
e_{k,h}=y_{o_k+h}-\widehat y_{o_k+h\mid o_k}.
\]

报告不同 \(h\)、时期和业务子群的 MAE/RMSE/偏差；比例误差只在分母语义和零值处理明确时使用。
模型必须与朴素基线在完全相同的切分、预测期和指标上比较。

### 4.3 不确定性

若预测进入库存、定价、排程或配置，优先输出分位数、区间或场景。区间同时报告名义覆盖率、经验
覆盖率和平均宽度；仅有点预测时，不得把预测值当成确定常数进入优化。

## 5. 表格机器学习的竞赛级协议

1. 先固定训练、验证、测试角色；测试集只用于一次最终评估；
2. 预处理、特征筛选和调参放入训练内管道；搜索过模型族时用嵌套验证或独立验证层；
3. 类别不平衡时同时报告 PR 指标、阈值下 Precision/Recall 和与题意一致的错误成本；
4. 概率用于风险或决策时检查校准；特征重要性只表示模型依赖，不自动表示因果作用；
5. 树模型是强表格基线；深度模型只有在样本量、结构和训练外证据支持时升级；
6. KNN 必须训练内确定尺度、距离、\(k\) 和权重；KD/Ball tree 在高维可能退化。

## 6. 预测—优化闭环

设未来不确定量为 \(\xi\)，决策为 \(x\)。不能只求

\[
\min_{x\in\mathcal X(\widehat\xi)} c(x,\widehat\xi),
\]

再把该点解写成稳健方案。推荐流程：

1. 用训练外残差、分位数或经核验的机制生成场景 \(\xi^{(1)},\ldots,\xi^{(S)}\)；
2. 写清决策在不确定量实现前还是实现后作出，禁止时间穿越；
3. 选择期望成本、机会约束、鲁棒集合或 CVaR 等与题意一致的风险准则；
4. 在滚动历史窗口中重演“当时可见信息 → 预测 → 决策 → 实现结果”；
5. 报告 realized cost、约束违反率、尾部损失和相对简单策略的 regret；
6. 对最终方案重新计算全部目标分项、slack、单位和执行顺序。

预测指标更优不保证决策成本更低；模型选择可以看决策损失，但该选择仍须隔离最终测试期。

## 7. 优化与启发式的选用顺序

优先检查是否可写为 LP/MILP、凸规划、CP-SAT、动态规划、最短路、最大流、匹配或选址模型。精确
模型即使只解小规模，也可用于验证启发式编码、约束和目标。

只有在非凸、组合规模或黑箱目标使精确方法不可行时再用模拟退火、遗传算法、差分进化等。最低
报告包括：编码、邻域/算子、约束处理、种群或温度、函数调用预算、随机种子、多次运行分布、基线、
小例精确对照和时间—质量曲线。没有可验证下界或最优性证书时，只能称“当前最好可行解”。

## 8. 国赛 C 题常用但容易误用的技巧

- **先做长表审计再透视**：保留原始主键和时间，不让透视表掩盖重复；
- **先定义标签再冻结可用信息**：防止结局后变量、累计全期量和未来窗口泄漏；
- **分层看误差**：总体均值可能掩盖关键地区、品类、设备或极端时期的失败；
- **把规则写成约束**：文字中的“至少、至多、连续、互斥、轮作、容量”均应可计算；
- **给不可行模型诊断**：输出违反的约束、必要松弛量和数据冲突，而不是只换启发式；
- **控制模型链长度**：每增加一层都写输入、输出、误差和下游用途；无用途的聚类/评价不加入；
- **复算关键数字**：摘要、表格、图和正文均来自同一机器可读结果，不手工抄写；
- **图表服务于判别**：展示数据质量、结构、训练外性能、方案权衡和稳健性，不用装饰性图替代证据。

## 9. 必须拒绝的“技巧”

- 随机划分时间序列或重叠窗口；
- 全数据插补、标准化、PCA、特征筛选后再交叉验证；
- 用测试集反复选模型、阈值或图形结论；
- 把相关、关联规则、SHAP 或特征重要性写成因果；
- 把单次随机运行、收敛曲线或求解器返回值写成全局最优；
- 只比较复杂模型，不给朴素基线；
- 预测—优化只传点预测，不做情景或误差传播；
- 以“历年 C 题常用”为理由套用熵权、灰色预测、神经网络或遗传算法。

## 10. 论文中的最小证据链

论文方法部分至少能回答：

1. 数据怎样从原始附件变成分析样本；
2. 每个模型为何与目标和数据结构匹配；
3. 基线、切分、指标和调参怎样保持公平；
4. 上游误差怎样传递到下游结论或决策；
5. 最终方案是否可行、稳健、可执行；
6. 哪些结论只是样本内关联，哪些得到训练外或外部证据。

## 11. 实现资源与调用边界

GitHub 仓库只作为官方实现入口，不承担题目事实、参数或算法优越性的证明：

| 任务 | 第一方仓库 | 用途边界 |
|---|---|---|
| 通用表格 ML、预处理、指标 | `scikit-learn/scikit-learn` | 记录实际版本；切分和业务口径仍由建模者负责 |
| 统计模型、回归、时序 | `statsmodels/statsmodels` | 诊断和推断依赖模型假设，不能只看成功拟合 |
| 大批量统计预测与基线 | `Nixtla/statsforecast` | 自动模型仍须滚动回测；仓库性能宣传不直接入库 |
| CP-SAT、路由、流、线性优化 | `google/or-tools` | 先核对模型类型、状态、界和版本 |
| LP/MIP/QP 求解器 | `ERGO-Code/HiGHS` | 记录 gap、容差、状态和数值尺度 |
| 凸优化建模 | `cvxpy/cvxpy` | DCP/DQCP 规则与所用求解器能力分开记录 |
| 代数优化建模 | `Pyomo/pyomo` | Pyomo 是建模层，不等于求解器或最优性保证 |
| 深度学习 | `pytorch/pytorch` | 固定张量、损失、训练/评估模式、随机性和版本 |
| 图与网络 | `networkx/networkx` | 适合建模和原型；大规模性能需另做基准 |
| 超参数优化 | `optuna/optuna` | 搜索过程必须嵌套在训练层，测试集不可参与 |

详细版本与来源边界见
`来源资料/自动学习/2026-08-21_GitHub算法资源与C题工作流复核.md`。

## 12. 输出前 C 题专用检查

- [ ] 所有附件的文件、表、行、列、主键、时间和单位均有清单；
- [ ] 训练样本和预测对象的生成时点一致，没有未来信息；
- [ ] 每问都有最简单基线，复杂模型的增益在训练外成立；
- [ ] 评价指标与题目代价一致，概率结论有校准或覆盖证据；
- [ ] 预测误差已传播到方案，极端情景下约束仍被检查；
- [ ] 优化状态、界/gap、违反量、整数性和目标重算均已输出；
- [ ] 多随机种子、关键参数敏感性和结论翻转点已报告；
- [ ] 所有外部事实、规则、软件行为和数据许可已按任务日期核验；
- [ ] 摘要中的每个数字可追溯到固定数据和代码输出。
