# 来源、版权与公开政策

本政策区分“本地证据保存”“知识吸收”和“GitHub 再分发”。三者不是同一授权。

## 可以进入 Git 的内容

- 原创知识正文、方法卡、模板和说明；
- 原创路由、测试和审计工具；
- 不包含受限原文的来源元数据、哈希、访问日期和审读结论；
- 已确认允许公开的最小合成例题与代码。

## 默认不进入 Git 的内容

- 第三方论文全文、扫描页和截图；
- 竞赛题目附件与原始数据包；
- 从网站保存的 HTML、图片和压缩包；
- 未确认作者关系或许可证的外部代码；
- 个人联系信息、账号、凭据和本机私有路径；
- 许可证或访问条件不允许再分发的材料。

`.gitignore` 是第一道分发边界，`tools/validate_github_release.ps1` 是提交后的机械检查。两者不能替代人工版权判断。

## 证据等级

| 等级 | 典型来源 | 在知识库中的角色 |
|---|---|---|
| A | 官方规则、官方数据、标准、原始论文 | 支持明确范围内的规则、定义或理论 |
| B | 同行评审论文、权威教材、官方软件文档 | 支持方法条件和实现语义 |
| C | 获奖论文、机构技术报告 | 案例与候选做法 |
| D | 博客、课程笔记、论坛、README | 发现线索 |
| U | 无法定位或只凭记忆 | 不得写成事实 |

来源等级必须绑定具体主张。官方页面可以证明奖项身份，但不能自动证明学生论文中的每个公式正确。

## 外部代码

GitHub 星标、fork 数和 README 声明不能证明数学正确或作者关系。吸收外部代码前至少记录仓库所有者、固定 commit、许可证、与论文作者或机构的关系、依赖版本和关键文件哈希；运行前做静态安全检查，并在隔离目录执行最小例、边界、不变量和必要的多种子测试。

## 个人信息和密钥

公开前检查电子邮箱、姓名与学校映射、绝对路径、API 密钥、访问令牌、私钥、账号和日志。即使信息曾在论文中公开，也只保留完成证据追溯所必需的最小信息。

## 许可证边界

本仓库已经明确采用：

- 原创软件代码及软件型配置：MIT License；
- 原创文档、方法卡、模板和说明文字：CC BY 4.0；
- 第三方材料：不属于上述授权，继续受其原版权和访问条件约束。

精确范围与建议署名见根目录 `LICENSES.md`。CC BY 4.0 允许包括商业用途在内的分享和改编，但要求合理署名、链接许可证并说明修改；任何许可证都不能覆盖仓库所有者无权重新授权的第三方材料。

## 公开发布门禁

```powershell
./tools/validate_github_release.ps1 -PublicRelease
```

该命令应把缺少许可证、邮箱样式内容、疑似密钥、受限来源路径和超大文件视为失败。通过仍不等于完成法律意见；权限不明时保持私有并人工核验。
