# 数学建模知识库

本目录是数学建模任务的长期知识底座。机器调用不以本 README 作为路由事实源：新任务先读取
[永久质量核心](00Q_永久质量核心.md)，再由 `tools/route_knowledge.ps1` 按
`routing-manifest.yaml` 返回当前阶段所需的最小文件集合。

> 当前版本说明：本库采用“永久质量核心 + 唯一路由清单 + 分阶段门禁 + 专题正文 + 来源台账”的结构。
> 获奖论文只作为案例证据，不作为公式或事实的权威来源；公式、数据和规则必须独立核验。

## 一、调用架构

1. **永久层**：每次正式建模只常驻 `AGENTS.md` 与 `00Q_永久质量核心.md`。
2. **路由层**：`routing-manifest.yaml` 是唯一手工维护的机器路由；
   `00B_任务路由与最小读取集.md` 只是由它生成的人类可读视图。
3. **阶段层**：数据阶段读取 `00D`，选模及验证设计阶段读取 `00E`，编码阶段读取 `15`，
   首次正式模型比较和结论前读取 `11`，正式交付时再读取 `12/13` 及必要规则。
4. **专题层**：路由只返回当前任务所需的方法卡；案例、复盘、网站映射和 `sources/` 延迟加载。
5. **维护层**：修改路由只编辑 manifest；生成路由表后运行黄金路由测试和全库机械审计。

典型调用：

```powershell
tools/route_knowledge.ps1 -ListRoutes
tools/route_knowledge.ps1 -RouteId regression_general -Stage model_selection,validation_design
```

回归任务默认读取轻量入口 `35_回归模型选择与方法总览.md`；只有短入口不足、需要完整方法公式或
属性表，或相应分支没有独立方法卡时才读取 `35A_回归模型完整方法索引.md`。

## 三、模型选择的总原则

模型不是越复杂越好。优先选择能在数据质量、时间、算力和解释要求下完成目标的最简单模型，
并用更复杂模型做对照。一个合格模型至少要同时说明：

- **对象**：研究的系统边界和变量是什么。
- **目标**：预测、解释、评价、分类、优化还是仿真。
- **假设**：哪些现实被保留，哪些被忽略。
- **关系**：变量之间的数学结构。
- **求解**：算法、参数、初值和停止条件。
- **证据**：拟合、外推、敏感性、稳健性或基准比较。
- **局限**：数据偏差、结构误设、适用范围和不可识别性。

## 四、知识更新约定

1. 原始资料放入新建的 `sources/` 子目录；不要覆盖原文件。
2. 阅读后用 `资料消化模板.md` 生成方法卡片或专题补充。
3. 新结论必须写明适用条件，不能只记录公式。
4. 代码、参数和结论能复现时才算真正沉淀。
5. 对既有结论有修正时，在 `CHANGELOG.md` 记录日期、原因、证据和影响范围。
6. 一次任务结束后用 `建模复盘模板.md` 记录“有效做法、失败尝试、可复用代码、下次改进”。
7. 维护知识库时读取 `00C_知识条目与证据维护规范.md`，并在完成前运行
   `tools/validate_library.ps1`；历史内容缺少逐条来源时如实标记，不能补造引用。

## 五、Codex Skill 与 GitHub 分发

- 本目录同时是本机 `math-modeling-library` Skill 的唯一知识源；`SKILL.md` 只负责触发、
  根目录解析、最小路由和阶段门禁，不复制专题正文。
- 当前 GitHub 镜像为私有仓库：
  <https://github.com/Strider002/math-modeling-library>。
- 本机安装使用目录联接指向本目录，因此知识更新无需复制第二份 Skill。
- Git 仓库只分发已维护的知识正文、路由、测试、工具和可审计的文本记录。
  `sources/原文/`、`sources/国赛/`、`sources/美赛/`、`sources/GitHub方法/` 以及
  PDF、图片、压缩包、Excel 和网页快照默认保留在本地，不通过 GitHub 再分发。
- 每次推送前先运行 `tools/validate_library.ps1` 和
  `tools/validate_github_release.ps1`；未来转为公开仓库前还需单独完成版权、署名、
  联系信息和许可证审查。

## 六、一句话工作准则

**先定义问题，再检查数据；先做基线，再加复杂度；先核验来源与公式，再解释结果。**
